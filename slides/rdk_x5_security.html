问题：可见光监控的三个硬伤

Problem & Approach
⚠️ 现有方案做不到
  • 暗光即失效：夜间可见光基本失明；
  • 没有深度：画面无法量化距离，误报难抑制；
  • 只能记录：不能拦截、驱离、联动门禁。
🎯 本方案的应对
  • 雷达测距：360° 点云，不依赖光照；
  • 量化判定：距离 / 点数 / 持续时间三重防抖；
  • 现场反制：门禁 + 声光 + 抓拍存证。
✓ 10 TOPS BPU 边缘算力
✓ 360° / 12Hz 雷达扫描
✓ 双摄 1080P + 720P
✓ 全链路本地闭环 · 0 云端依赖
这段是"为什么不用现成摄像头"的回答。三条一一对应右侧三条，讲的时候用手指对应，别分两遍说。

系统架构

System Architecture
架构只讲一句话：从下往上是"采样—判定—呈现"，从上往下是"下发—执行"。四层都在同一块板子上，没有任何云端环节，这是能做到断网可用、断电自恢复的前提。

核心机制 ①　雷达防区与三级判定

Radar Pipeline
STEP 01

→
STEP 02
背景自学习开机 3 秒标定，剔除固定物
→
STEP 03
欧氏聚类0.18m 成簇，≥5 点去噪
→
STEP 04
三级状态机空间 / 数量 / 时间三重防抖
🟢 正常 STANDBY
防区内无目标或点数不足。
绿灯常亮，系统待机。
🟡 警告 WARNING
有点数但持续不足，或距离处于边缘。
黄灯常亮，提示关注。
🔴 报警 ALARM
点数达阈值且持续时间达标。
红灯 + 蜂鸣器 + 抓拍存证。
防区 315°~45°（跨 0°）
距离 0.1~8.0m · 阈值 0.5m
连续计数 ≥10 · 保持 0.2s
参数在线热更新并落盘
重点是"三重防抖"：距离、点数、持续时间任意一个不满足都不报警，这是把误报压下去的关键。参数可以现场在线改，不用重启。

核心机制 ②　双生物识别 + 机械门禁

Access Control
① 人脸
InsightFace SCRFD 检测 + ArcFace 512 维；≤35° 侧脸直接拦截，正脸才比对；阈值 0.35 可调。
→
② 指纹
ML-FPM007 UART 直连；1~100 编号录入，同指三次采集确认；Touch 唤醒省电，非法试探联动声光。
→
③ 执行
舵机齿条门禁 360° 连续旋转 + 齿条传动；开度 0~100% 实时落盘，断电不丢步，行程 5.3s。

ArcFace 人脸特征
≤35°

<1%
门禁开度误差 · 断电不丢步
识别通过 → 自动开门 → 抓拍存证 → 事件入库，全程无需人工值守。
强调"识别 + 执行"是一体的：只识别不开门等于没做。开度用毫秒级时间微积分做虚拟编码器，所以断电重启不丢步，这是实机验过的。

边缘感知：算力用在刀刃上

Multimodal Sensing
🧲 BPU 视觉检测
YOLOv8 走 10 TOPS BPU 硬件加速，主 CPU 近零占用；无人观看时停取帧，算力按需分配。
🎥 双摄管线
主摄 1080P + 副摄 720P MJPEG；无人观看自动降到 2 FPS 节能，掉电自愈、曝光自适应。
🔨 声学破拆 + 🔥 超温联动
ADS1115 16 位差分采集，80mV / 30ms 识别暴力冲击；AHT10 ≥45°C 联动声光，响应 ≤1s。
📟 现场交互
SSD1306 OLED 显示访客字幕 / 反色火警弹窗；ES8326 车规声卡全双工对讲 + 门铃应答。
六类感知共用一条事件总线：任一子系统触发，都走同一套「存证 → 推送 → 联动」路径。
这一页回答"为什么要这么多传感器"：雷达管空间、视觉管身份、声学管破坏、温湿度管火情，各自覆盖一种失效场景，不重复。

🧭 已知边界
  • 遮挡：单雷达存在阴影区，拐角需补点；
  • 人数：密集人群聚类会粘连，阈值需现场标定；
  • 识别：人脸库规模在百级，未做万级检索优化。
下一步
  • 双雷达拼接消除遮挡盲区；
  • 事件云端归档（可选，不依赖）；
  • BPU 模型量化压缩，换取更高帧率。
主动说边界，比被问出来强。遮挡和密集人群是这套方案真实的弱项，说清楚再给下一步，评委会认为你想过。
