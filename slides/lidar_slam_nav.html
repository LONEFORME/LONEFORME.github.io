问题：单传感器都会退化

Problem & Motivation
⚠️ 各自的失效场景
  • 轮式里程计：地毯 / 湿滑地面打滑，速度积分漂移；
  • 视觉里程计：弱纹理白墙、玻璃反光、光照突变失效；
  • 纯 IMU：加速度计噪声随时间平方级累积，二次积分发散。
🎯 为什么是 LIO
  • 几何约束不挑环境：点云直接测距，弱纹理 / 暗光都有效；
  • IMU 补帧间运动：250Hz 预积分抵消雷达帧内畸变；
  • 地图级一致约束：新帧对既有地图配准，漂移被持续拉回。
✓ 宇树 L1：2100 点/帧 @ 10Hz
✓ IMU 250Hz
✓ 双算法互备
✓ 0 云端依赖
这一页别讲技术细节，讲"为什么不能只靠一个传感器"，三条失效场景每条一句就够了。

双定位链并行架构

Dual Positioning Chains
两条链是"并行不耦合"：T265 独立成链，用来对照 LIO 有没有跑飞，而不是拿去融合。双脑是为隔离实时任务——Linux 卡死不影响底层飞控链路。

核心算法 ①　FAST-LIO2 流水线

Algorithm: FAST-LIO2
01
IMU 前向传播250Hz 预测状态与协方差
→
02
点云去畸变按帧内运动逐点补偿
→
03
IEKF 迭代雷达与 IMU 同一误差状态内收敛
→
04
ikd-Tree 增量地图新点插入 / 旧点删除，无需重建
🌳 增量地图
最近邻查询近似 O(logN)，室内小场景实时性最好；地图可导出 PCD。
📐 直接法配准
点到线 / 点到面残差，跳过特征提取，弱几何环境也能收敛。
⚡ 为什么做主算法
本仓已实调宇树 L1 室内参数；Point-LIO 不佳时的备用链路。
只讲一件事：FAST-LIO2 强在"地图一致"。ikd-Tree 让新帧增量挂到地图上，所以长走廊不会越走越歪。

核心算法 ②　Point-LIO 与双算法取舍

Point-LIO vs FAST-LIO2
维度FAST-LIO2Point-LIO
更新粒度帧级（整帧对地图）点级（逐点即时）
地图结构ikd-Tree 增量地图滑动状态，无全局地图
剧烈运动较好更平滑
建图导出支持 PCD不支持
内存占用随地图增长稳定
本仓定位主用 / 备用互切L1 默认链路
🛠️ 实战用法
  • 宇树 L1 默认跑 Point-LIO（unilidar_pointlio.launch）；
  • 效果不佳一键切 FAST-LIO2 备用链；
  • imu_en 必须开启——关掉 IMU 参与，LIO 直接退化；
  • 两套算法共用同一份点云与 IMU 输入，切换不改硬件。
结论：不是二选一，是互为冗余
被问到"为什么用两个算法"就答这个：它们失效场景不一样，互备比调参更可靠。切换是改 launch，不改硬件。

参数调优与避坑清单

Tuning & Pitfalls
⚙️ FAST-LIO2 室内优化（laser_mapping.yaml）
  • 体素网格 0.5 → 0.12m：室内特征锐化约 4 倍；
  • 探测范围 100 → 20m：滤掉窗外阳光噪点，CPU 负载下降；
  • point_filter_num: 1：保留全部采样点；
  • 输出 /Odometry：实时 6-DOF 里程计。
🪤 三个真踩过的坑
  • imu_en 关不得：关掉 IMU，LIO 直接退化；
  • 启动前清共享内存：rm /dev/shm/fastrtps_*，否则 Fast DDS 起不来；
  • IMU 自检 20~30s：等初始化完成再取数据；
  • Point-LIO 不佳时切 FAST-LIO2，别硬调参。

边界与下一步

Limits & Next
🧭 当前边界
  • 单雷达遮挡：一根 L1 有视野盲区，贴墙拐角会丢特征；
  • 非重复扫描稀疏：单帧点少，静止时地图长得慢；
  • 算力上限：N100 跑 LIO 尚可，加视觉重定位会吃紧；
  • 无回环：长距离往返的累积误差靠 T265 对照发现，未做闭环校正。
🚀 下一步
  • 加回环检测 / 位姿图优化，压长距离漂移；
  • 点云地图导出 + 离线重定位，支撑导航复用；
  • 与 2D 雷达融合，补齐地面障碍；
  • 时间同步统一到 PTP / 硬触发，进一步降畸变。
"无回环"这条要主动说：评委一定会问长距离漂移，先承认再给方案，比被问住强。
