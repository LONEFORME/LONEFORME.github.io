## 2. 八大核心技术栈详细知识点与自学资源

### 模块一：核心编程语言基础栈

无人机系统严格遵循“底层求极速与确定性、顶层求敏捷与算力库”的双语言架构。

#### 1. C 语言（面向微控制器 / 飞控核心开发）
- **为什么需要**：单片机（MCU）算力有限，需要微秒级响应，C 语言具备直接操作内存与外设寄存器的能力。
- **必备知识点清单**：
  - **基础语法与控制流**：基本数据类型（`uint8_t`, `int16_t`, `float`）、流程控制（`if-else`, `switch-case`, `for`, `while`）、函数定义与作用域；
  - **内存与指针操作（核心重点）**：指针变量、取地址符（`&`）、指针解引用（`*`）、指针运算、空指针判断。飞控接收到的每一个通信字节包，本质上都是在内存连续地址上通过指针进行解析；
  - **复合数据类型**：结构体（`struct`）、联合体（`union`）、枚举（`enum`）。用于将无人机的姿态角、速度、坐标打包成一个紧凑的数据对象；
  - **位运算操作（Bitwise）**：与（`&`）、或（`|`）、异或（`^`）、左移右移（`<<`, `>>`）。用于配置单片机寄存器、设置与检测状态标志位（Flag）；
  - **模块化工程管理**：头文件保护（`#ifndef ... #endif`）、多源文件组织（`.h` 与 `.c` 分离）、外部变量声明（`extern`）、条件编译。
- **推荐自学资源**：
  - **文字教程**：[菜鸟教程 · C 语言教程](https://www.runoob.com/cprogramming/c-tutorial.html)（查语法极快，适合零基础对照代码快速理解）；
  - **视频教程**：Bilibili **浙江大学 翁恺老师《C 语言程序设计》**（经典神课，把指针和内存模型讲得入木三分）。
- **对应仓库资产**：`01_锡月/01_飞控固件`、`02_凌霄/固件基线`、`05_凌霄官方原厂资料包/01-飞控源码`。

#### 2. Python 3（面向机载微电脑 / 视觉与算法大脑）
- **为什么需要**：图像处理、路径规划与决策逻辑复杂，Python 开发周期短，拥有丰富的科学计算与视觉库。
- **必备知识点清单**：
  - **面向对象与模块化**：类（Class）、方法、实例属性、模块导入机制（`import`）；
  - **科学计算与矩阵运算**：`numpy` 库（多维数组 `ndarray` 切片、矩阵转置、向量模长计算、空间坐标几何运算）；
  - **串口硬件交互**：`pyserial` 库（打开串口、配置波特率、二进制字节流读写 `ser.write(bytes)` 与 `ser.read()`）；
  - **多线程与并发**：`threading.Thread`、`multiprocessing`、线程安全队列 `queue.Queue`。用于将耗时的“图像处理线程”与高频实时的“串口通信线程”解耦，防止通信卡死。
- **推荐自学资源**：
  - **文字教程**：[菜鸟教程 · Python 3 教程](https://www.runoob.com/python3/python3-tutorial.html)、[廖雪峰 Python 教程](https://www.liaoxuefeng.com/)；
  - **视频教程**：Bilibili **黑马程序员 Python 快速入门** 或 **B站各类高赞 Python 零基础实战精讲**。
- **对应仓库资产**：`01_锡月/02_树莓派机载主控`、`02_凌霄/自研系统`（原 03 仓 RDK X5 机载资产 2026-10-01 并入）、`03_激光雷达SLAM避障`、`04_OpenCV视觉检测系统`。

### 模块二：硬件电路、结构建模与物理装调栈

- **为什么需要**：无人机运行在真实物理环境中，机械震动过大、电源压降过深、支架断裂会导致任何优秀算法瞬间失效。
- **必备知识点清单**：
  - **电子技术与分级供电**：
    - **弱电与强电隔离**：动力锂电池高电压（3S: 11.1V~12.6V, 4S: 14.8V~16.8V）通过分电板直接驱动电机；
    - **DC-DC 开关降压电源（BEC）**：为机载电脑提供稳定高功率 5V/3A~5A 供电；
    - **低压差线性稳压器（LDO）**：将 5V 降压为极其纯净的 3.3V 为单片机核心及陀螺仪芯片供电；
    - **常见硬件总线标准**：UART（TTL 电平，TX/RX 交叉连接）、I2C（SCL/SDA 上拉电阻）、SPI（MOSI/MISO/SCK/CS 高速总线）。
  - **旋翼动力学体系**：
    - **无刷电机与电调**：电机定子尺寸（如 2205/2306）、KV 值物理意义；电调（ESC）三相方波换向驱动原理；
    - **螺旋桨配比与推重比**：正反桨安装方向（CW/CCW）；整机自重与四轴最大总拉力之比，赛用机推重比要求保持在 2:1 ~ 2.5:1；
    - **锂聚合物电池（LiPo）安全**：单片标称 3.7V、满电 4.2V、过放截止保护 3.5V；放电倍率 C 数与平衡充电常识。
  - **三维建模与 3D 打印快速打样（电赛四天三夜刚需）**：
    - **三维 CAD 结构建模**：使用 **SolidWorks** 绘制机载电脑固定座、摄像头俯角减震支架、激光雷达托架、电池防脱落卡扣；
    - **切片与 3D 打印**：使用 **Bambu Studio（拓竹切片软件）** 配置填充率、壁厚、支撑结构，使用拓竹 3D 打印机快速成型实物零件。
  - **硬件 EDA 与 PCB 电路板设计（自制分电板与转接板）**：
    - **EDA 软件选型**：首选 **立创 EDA（标准版/专业版）**（零门槛在线绘制、元件库全面、与嘉立创打样无缝打通），进阶可学 **Altium Designer (AD)**；
    - **绘制规范**：原理图元器件引脚脚位匹配、大电流动力走线（≥2mm 宽线或开窗镀锡）、地平面（GND）大面积铺铜、高频小信号（I2C/SPI 陀螺仪线）远离电机动力强电磁干扰线；
    - **加急打样**：掌握将 Gerber 文件上传至嘉立创进行 24 小时加急免费打样流程。
  - **任务载荷与机载执行器驱动电路**：
    - **激光瞄准指示**：利用 N-MOSFET（如 AO3400）搭建电子开关电路驱动机载红色/绿色激光发射管（满足 2017-C 追踪、2022-B 瞄准）；
    - **物资投放机构**：微型舵机挂钩释放或电磁铁断电脱钩机构（满足 2018-B 灭火、2023-G 消防投弹）；
    - **声光警报**：高分贝有源蜂鸣器与高亮 LED 强光爆闪驱动电路（满足 2025-H 动物驱赶与声光指示）。
- **推荐自学资源**：
  - **PCB 设计与打样**：Bilibili **嘉立创官方硬件基础入门系列 / 凡亿 PCB 入门视频**；
  - **3D 建模**：Bilibili **SolidWorks 零基础入门教程（如生工小成、野火画板外壳教程）**；
  - **3D 打印实操**：Bilibili **拓竹官方教程（Bambu Lab 快速上手、切片参数设置）**。
- **对应仓库资产**：`05_凌霄官方原厂资料包/05-硬件相关资料/ANO_LX_V1.3原理图.pdf`、`06_3D打印结构模型库/`（机架配件、电机防护罩、双目云台与减震座的 SolidWorks 源文件与拓竹 3MF 切片工程）。

### 模块三：嵌入式飞控与底层控制理论栈

- **为什么需要**：四旋翼无人机是不稳定欠驱动系统，飞控程序必须以每秒数百次的高频率实时计算电机输出，保持姿态平衡。
- **必备知识点清单**：
  - **STM32 单片机硬件外设**：
    - **定时器（TIM）**：输出 50~400Hz 高精度 PWM 信号驱动电调，调整占空比；
    - **中断机制（NVIC）**：外部按键中断、定时器更新中断、串口中断与优先级抢占；
    - **DMA（直接内存访问）**：无需 CPU 干预，由 DMA 搬运高速串口数据流。
  - **嵌入式实时操作系统（RTOS）**：
    - 任务优先级抢占调度、时钟节拍、信号量（Semaphore）、互斥锁（Mutex）、消息队列；
    - 实操对象：`uCOS-III`（锡月工程实战）或 `FreeRTOS`。
  - **控制理论与姿态解算**：
    - **欧拉角与滤波**：横滚（Roll）、俯仰（Pitch）、偏航（Yaw）；一阶低通滤波与互补滤波/EKF 姿态融合；
    - **串级 PID 控制器**：外环角度求期望角速度，内环角速度求电机差速输出；
    - **高度定高闭环**：基于 ToF 激光/气压计的纵向加速度-速度-高度三阶 PID。
  - **核心室内定点悬停传感器：光流计（Optical Flow）与 ToF 激光定高二合一模块**：
    - **为什么必须掌握**：在没有 GPS 的室内赛场，双目 VIO（如 T265）成本高且算力开销大，而**光流+ToF 测距一体化模块（如 LC302 / PMW3901 + VL53L1X）**仅重数克，成本极低；
    - **工作原理**：模块通过底视微型摄像头连续抓取地面纹理像素的相对位移速度，结合激光 ToF 测得的实时对地高度 H，换算出无人机水平对地速度 (vx, vy)，输入飞控速度环实现米级/厘米级“钉在空中”的稳定自控悬停。
  - **无线遥控链路与接收机通信协议（安全第一道防线）**：
    - **通信协议**：**SBUS**（100kbps 负逻辑反相串口协议，单根信号线传输 16 个遥控通道）、**IBUS**、**ELRS (CRSF)** 与 **PPM**；
    - **摇杆通道映射**：通道 1~4 对应横滚（Aileron）、俯仰（Elevator）、油门（Throttle）、航向（Rudder）；
    - **紧急救机与失控保护（Failsafe）**：设置 AUX 辅助通道开关，在无人机自主巡航失控或跑偏时，能够一秒切回人工手动接管或触发紧急断电锁桨（防止炸机伤人）。
- **推荐自学资源**：
  - **STM32 终极启蒙教程**：Bilibili **江协科技（原江科大自动化协创团队）STM32教程**（嵌入式领域公认天花板级教程，把 Keil 使用、引脚外设、PWM、串口讲得深入骨髓，大一新生必看！）；
  - **光流悬停与飞控实战**：Bilibili **匿名科创官方团队 ANO_LX 飞控源码讲解视频（光流融合篇）**；
  - **PID 控制原理直观理解**：Bilibili **《忠厚老实的高三同学：现代控制理论/PID 通俗讲解》** 或 **稚晖君各类机器人控制讲解**。
- **对应仓库资产（两大飞控路线对比学习）**：
  - **方案 A（自研全开源路线）**：`01_锡月/01_飞控固件/BirdFlight_V2.0/`（基于 STM32F405 + uCOS-III，自研串级 PID / ADRC / LQR 算法在 `Control/` 目录完全开源，串口固定 **`230400` bps**）；
  - **方案 B（工业级闭环路线）**：`02_凌霄飞控与空地协同/官方资料/固件基线/` 与 `自研系统/飞控源码/`（基于 STM32F407 + 匿名闭环 136 IMU 核，上位机通过 `0x41` 实时速度帧控制，串口固定 **`460800` bps**）。
  - **硬件底座原理图**：`05_凌霄官方原厂资料包/06-原理图_PCB/` 与 `01_锡月/06_官方培训资料包/1、入门/无人机教学试验平台资料/03. 飞控原理图/`。

### 模块四：嵌入式开发板选型全景与机载边缘平台栈（从 01科技 K230 到 RDK X5）

- **为什么需要**：无人机的“大脑”不能盲目上最高配置，必须根据赛题任务重量限制、开机启动速度与算力需求做科学的硬件选型。

#### 1. 电赛与机器人嵌入式开发板的三大分级体系
在本地工作区（详见根目录 `boards/` 与 `.agents/skills/embedded-board-setup/`）中，我们维护了 7 款主流开发板，对大一新生而言，核心要分清三类硬件定位：

```
[微控制器 (MCU)]         ──► [微型 AI 视觉模组]           ──► [单板边缘计算机 (SBC)]
• 芯片：STM32F4/F1          • 模块：01科技 CyberCAM K230      • 主机：地平线 RDK X5 / 树莓派
• 系统：裸机 / RTOS         • 系统：双核 RISC-V + CanMV      • 系统：完整 Ubuntu Linux + ROS2
• 算力：无 AI / 纯电控      • 算力：1~2 TOPS (KPU 加速)       • 算力：10 TOPS (BPU/NPU 强算力)
• 优势：微秒响应、超低延迟  • 优势：15克极轻、1秒冷启动       • 优势：跑激光SLAM、3D点云与大模型
• 定位：底层飞控平衡手脚    • 定位：轻量级巡线与靶标找色     • 定位：多传感器全自主导航大脑
```

#### 2. 01科技 CyberCAM K230 核心技术栈与实战开发
- **为什么在无人机电赛中推崇 01 科技 K230？**
  - **极致超轻与极低功耗**：整板仅重十几克，微型无人机也能轻松挂载，完全不牺牲电池续航；
  - **秒级开机**：不同于跑 Linux 系统需要等 30 秒开机，K230 上电 1~2 秒即可开始稳定输出图像和识别坐标，非常适合电赛掐秒开赛的紧张节奏；
  - **零门槛免编译（CanMV IDE）**：使用 **MicroPython** 脚本语言开发，插入 USB 即可在电脑端实时单步调试图像与查看画面，开发周期以小时计。
- **必备知识点清单**：
  - **双核 RISC-V 架构常识**：小核运行 RT-Thread 实时系统控制传感器与外设，大核处理图像计算并调用硬件 **KPU 神经网络加速器**；
  - **CanMV IDE 开发环境**：固件烧录、在线连接调试、右侧实时图像与直方图窗口观察；
  - **基础机器视觉 API（MicroPython）**：
    - 图像初始化：`sensor.reset()`, `sensor.set_pixformat(sensor.RGB565)`, `sensor.snapshot()`；
    - 色块跟踪：`img.find_blobs([thresholds])` 直接输出最大色块的矩形外框、质心坐标 (cx, cy) 与旋转角度；
    - 二维码与条形码识别：`img.find_qrcodes()`、`img.find_barcodes()`；
  - **KPU 端侧 AI 模型转换与推理**：
    - 借助嘉楠官方 `nncase` 编译器工具，将电脑训练好的分类或轻量检测模型量化为 `.kmodel` 格式，拷贝进 TF 卡中在 MicroPython 代码中一键调用；
  - **硬件串口（UART）闭环输出**：
    - 使用 `from machine import UART` 配置硬件串口（如 UART1，波特率 115200），将识别到的靶心坐标打包成自定义协议包直接发送给底层 STM32 飞控。

#### 3. T265 硬件连接与冷启动避坑铁律（电赛现场血泪经验）
大一新生调试机载 T265 双目相机时，常常遇到“刚开机时识别不到 T265，必须手动拔插一次才能恢复”的抓狂故障，必须死记以下三点：
1. **接口严禁插蓝色 USB 3.0，必须插黑色 USB 2.0**：
   * 树莓派 4B 的蓝色 USB 3.0 主控（VL805）在开机上电瞬间发起的 SuperSpeed 时序握手存在 Bug，会导致 T265 芯片陷入硬件 PHY 死锁（内核报错 `Cannot enable. Maybe the USB cable is bad?` 且总线掉线），必须物理拔插断电；
   * 插在黑色 USB 2.0 接口上完全不受该 Bug 影响，480Mbps 带宽传输 6-DoF 坐标绰绰有余，开机脚本直接秒级自启加载固件！
2. **udev 权限必须使用 `:=` 终结赋值**：
   * 在 `/etc/udev/rules.d/99-realsense-libusb.rules` 中必须使用 `MODE:="0666"` 终结赋值，防止被系统其他规则篡改为 root 专属：
     ```udev
     SUBSYSTEMS=="usb", ATTRS{idVendor}=="03e7", ATTRS{idProduct}=="2150", MODE:="0666", GROUP:="plugdev"
     SUBSYSTEMS=="usb", ATTRS{idVendor}=="8087", ATTRS{idProduct}=="0b37", MODE:="0666", GROUP:="plugdev"
     ```
3. **备齐软件复位工具**：安装 `usbutils`，极端情况下可通过执行 `sudo usbreset 03e7:2150` 实现免拔插软复位。

### 模块五：ROS2 机器人操作系统与分布式中间件栈

- **为什么需要**：
  - 传统单体程序在同时接入双目相机、激光雷达、飞控串口和路径规划后，极易发生进程阻塞或一个线程报错导致整机瘫痪；
  - **ROS2（Robot Operating System 2）** 是现代智能机器人与自主无人机领域的“工业级标准通信骨架”。它将无人机的各个功能拆解为完全解耦的**独立节点（Node）**；
  - 工业界与学术界的雷达驱动、T265/D435 深度相机、开源激光 SLAM 算法（如 Fast-LIO、Point-LIO、Cartographer）几乎全部原生基于 ROS/ROS2 提供，掌握 ROS2 意味着能直接调用全世界开发者的成熟成果。
- **必备知识点清单**：
  - **核心通信机制**：
    - **节点（Node）**：单一功能的可执行单元（如一个节点专门负责读取激光雷达，另一个节点负责图像识别）；
    - **话题通信（Topic - Pub/Sub）**：高频、异步、多对多的单向广播数据流（例如相机节点向 `/camera/image_raw` 话题发图，视觉检测节点订阅该话题）；
    - **服务通信（Service - Client/Server）**：同步双向请求应答（例如地面站请求 `/takeoff_cmd`，飞控回复执行结果）；
    - **动作通信（Action）**：长周期、支持中途取消、带实时进度反馈的闭环任务（例如 `/navigate_to_waypoint` 飞往目标航点并持续反馈当前距离）。
  - **TF2 空间坐标变换体系（机器人学灵魂）**：
    - 理解机器人身上的多重物理坐标系：世界大地坐标系（`map` / `odom`）、无人机重心机体坐标系（`base_link`）、机载下视相机坐标系（`camera_link`）、激光雷达坐标系（`laser_link`）；
    - 掌握静态 TF 广播与动态 TF 查询，理解相机识别到的目标像素偏差如何通过 TF 树自动转换到大地绝对坐标系中。
  - **可视化调试与数据记录工具**：
    - **RViz2**：ROS2 专属三维可视化利器。无需起飞即可在 PC 屏幕上三维直观观察无人机位姿姿态、激光雷达点云切片与空间坐标系；

    - **ros2 bag**：离线数据录制与回放。在飞行现场录下所有传感器数据包，回实验室后像放电影一样反复回放排查算法 Bug。
  - **包管理与工程构建**：
    - 工作空间结构（`src/`）、包定义（`package.xml`）、构建工具 `colcon build`；
    - 使用 Python 编写 `launch.py` 启动脚本，一键顺序拉起全机数十个软硬件节点。

### 模块六：机器视觉与端侧深度学习感知栈（OpenCV + YOLO + 空间传感）

- **为什么需要**：无人机需要“看到”地面的引导黑线、色块靶标，更需要识别复杂的**手写数字、条形码、特定野生动物、火源与车辆**，并精确获取自身空间三维坐标。

#### 1. OpenCV 传统计算机视觉算法与相机反投影
- **适用场景**：规则几何图形（圆环、方框、十字交叉线、黑色导线）、单色色块靶心，计算极快（100fps+）、零训练成本、纳秒级响应。
- **必备知识点清单**：
  - **色彩空间转换（RGB 到 HSV）**：利用色相 H 通道实现抗赛场强弱光漂移的颜色精准提取；
  - **图像二值化与形态学滤波**：`cv2.inRange()`、膨胀与腐蚀、开闭运算消除反光与环境噪点；
  - **轮廓检测与几何拟合**：`cv2.findContours()` 提取边缘，拟合最小外接圆/矩形并根据长宽比与面积筛选真实靶标；
  - **质心计算与单目几何反投影**：通过空间矩求解目标在视野中的像素中心偏差 (Δu, Δv)，结合机载相机安装俯角与飞行高度 H，通过针孔投影方程将像素偏差直接反投影为空间物理位移偏差 (ΔX, ΔY)。

#### 2. YOLO 目标检测与端侧 NPU/BPU 硬件加速（复杂目标识别利器）
- **适用场景**：电赛高阶赛题中非单一色块的复杂目标识别（如 2024-D 题货架多位数字与条形码、2025-H 题野生动物不同物种图片分类、2023-G 题小车与火源）。此时传统色彩阈值完全失效，必须依赖深度学习目标检测。
- **为什么必须学“端侧部署与模型量化”？**
  - 在 PC 上跑 PyTorch 代码很简单，但无人机只能携带轻量级机载单板电脑（如地平线 RDK X5、RK3588 或树莓派）。如果不经优化直接用 CPU 跑浮点模型，帧率通常只有 2~5fps，会引起严重的飞行控制延迟并导致炸机；
  - 必须掌握**模型轻量化选型、模型格式转换与端侧硬件加速单元（NPU/BPU）的 INT8 量化部署**，让机载端以 30fps~60fps 高速推理。
- **必备知识点清单**：
  - **轻量化模型选型**：只使用 Nano 或 Small 级别轻量网络（如 `YOLOv5n/s`、`YOLOv8n`、`YOLO11n` 或 `YOLO-Fastest`）；
  - **数据集采集与标注规范**：用摄像头多角度采集 200~500 张现场目标图片，使用 **Labelme** 或 **Roboflow** 在线平台手动拉框标注，导出为 YOLO 标注格式（每行：`class_id x_center y_center width height` 归一化坐标）；
  - **PC 端训练与验证**：使用 Python 的 `ultralytics` 库调用独立显卡（GPU）进行 100~300 轮训练，获得最优权重文件 `best.pt`；
  - **模型格式转换与端侧硬件加速（电赛核心技术壁垒）**：
    - `PyTorch (.pt)` → `ONNX 通用跨平台交换格式`；
    - **地平线 RDK X5 平台**：使用地平线 OpenExplorer 工具链进行模型检查、校准与 INT8 定点量化，编译生成专用于 10 TOPS BPU 的 `.bin` 硬件模型，推理延迟降至 15ms 以内；
    - **树莓派 / 通用 Linux 平台**：使用 **NCNN** 或 **ONNXRuntime** 进行 CPU 多线程推理优化；
  - **目标框与飞控决策对接**：
    - 解析推理输出结果：检测框坐标 `[xmin, ymin, xmax, ymax]`、置信度分数 `conf`、类别 ID `cls`；
    - 计算预测目标框中心坐标 (cx, cy)，计算其相对于画面中心的偏差值，并丢弃置信度低于阈值（如 < 0.6）的误检结果。

## 4. 新时代工程师核心竞争力：熟练掌握 AI 协同开发

> **特别提醒**：大一新生面对海量的 C 语言寄存器手册、复杂的 Linux 命令或庞大的算法库，**千万不要死记硬背 API**。  
> 现代优秀工程师与电赛高手的核心竞争力之一，是**深度运用 AI 编程助手（如 Antigravity、Claude、ChatGPT）作为专属技术导师与副驾驶**，就像你现在与我对话一样，将你的工程思路快速落地。

### 4.1 AI 能在电赛备赛中为你做什么？

1. **解读“天书代码”与底层寄存器**：
   - 遇到飞控源码里看不懂的 DMA 配置、位运算或指针操作时，直接把代码片段发给 AI，让它“逐行注释并用通俗语言解释其物理含义”。
2. **极速定位 Bug 与编译报错**：
   - Keil 编译报错（如 `error: #20: identifier "xxx" is undefined`）或 ROS2 节点崩溃抛出异常时，把终端完整报错日志贴给 AI，它能秒级指出根因并给出精确的修改方案。
3. **初版驱动与通信协议快速生成**：
   - 比如你需要写一段“读取超声波测距高电平微秒数并换算为厘米”的代码，先用自然语言向 AI 描述需求，让它生成规范的驱动框架，你在此基础上微调验证。
4. **设计方案与算法头脑风暴**：
   - 看到新一届电赛赛题时，把赛题任务描述给 AI，让它列出可行的 2~3 种软硬件技术方案并对比优缺点，辅助团队做架构决策。

### 4.2 高效驾驭 AI 的三大沟通原则（Prompt 技巧）

- **原则一：交代上下文，不说空话**  
  - ❌ *错误提问*：“我的单片机代码报错了怎么办？”  
  - ✅ *高效提问*：“我正在 STM32F405 上使用 HAL 库配置 TIM1 的 PWM 输出，频率设为 400Hz 驱动电调，现在电机不转，以下是我的 `main.c` 和配置代码：……”
- **原则二：让 AI 给出解释，不要只抄答案**  
  - 要求 AI 说明“为什么要这样改，背后的原理是什么”，通过解决一个 Bug 彻底掌握该模块的知识点。
- **原则三：保持批判性思维，真实板端检验**  
  - AI 是强大的副驾驶，但它无法替你接线和拧螺丝。**AI 给出的代码必须经过你的逻辑审查，并最终在真实硬件（开发板、示波器、飞行台）上跑通验证。**

## 5. 大一新生的四大技术认知误区（避坑要点）

1. **误区一：“算法最重要，硬件无所谓”**  
   **真相**：在电赛现场测评中，绝大多数事故不是因为算法错误，而是因为：插反电源导致芯片烧毁、电机震动导致陀螺仪饱和、电容接触不良导致单片机频繁复位、螺旋桨动平衡太差引发共振。**硬件的扎实程度决定了系统的下限。**
2. **误区二：“一上来就要上深度学习 YOLO / 复杂神经网络”**  
   **真相**：电赛赛场的光斑、圆形靶标、红蓝双色、黑色导线，用基础的 **OpenCV 色彩空间分割 + 形态学轮廓查找** 即可达到 100fps 以上的超低延迟与极高准确率。盲目引入沉重的大模型只会消耗宝贵的机载算力和造成严重通信延迟。
3. **误区三：“把所有功能写进同一个主循环死循环”**  
   **真相**：在机载 Python 程序中，如果在主循环里直接写 `time.sleep()` 或同步等待一帧图像处理完成，飞控通信就会因为超时而触发丢控保护。**多线程并发、ROS2 节点解耦与状态机（FSM）是必须建立的代码架构思维。**
4. **误区四：“单打独斗，想一个人把软硬件全包”**  
   **真相**：电赛是 3 人协作的系统工程。大一阶段建立全栈广度认知，但在实战中，队伍必须清晰分工：一人主攻动力硬件与底层飞控调参，一人主攻机载算法、ROS2 与机器视觉，一人主攻通信交互、自制地面站与设计报告。
